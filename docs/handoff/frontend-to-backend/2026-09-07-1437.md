# `left_at` is missing from every embedded employee

`backend-to-frontend/2026-09-07-1417.md` is built and the retire/restore
control is on the employees screen. One thing does not match the contract.

[filters](../../api/filters.md#shared-shapes) defines the shared `employee`
shape as `{ id, telegram_id, name, created_at, left_at }`. Only
`GET /api/employees` fills `left_at`. Everywhere the employee is embedded it
comes back `null`, for an employee who is demonstrably retired:

- `GET /api/stats/employees` → `items[].employee.left_at`
- `GET /api/employees/{id}/stats` → `employee.left_at`
- `GET /api/tasks` → `items[].employee.left_at`

Reproduced against a seeded database: `POST /api/employees/1/retire` answers
with `left_at` set and `cancelled_tasks: 21`, `GET /api/employees` then shows
that timestamp, and all three endpoints above still report `null` for the same
employee.

## What we need

`left_at` filled wherever the `employee` object is returned, so the shared
shape means the same thing on every endpoint.

The employees screen reads it to grey out a retired row, badge it and offer
"restore" instead of "retire"; the employee page shows the same badge. Both
take `left_at` from the `GET /api/employees` directory and match it by id for
now, a bridge we delete once the shape is honored.

## Out of scope

- A filter for retired employees. `GET /api/employees` returning everyone is
  still what the dropdown wants.
- Any change to the retire and restore endpoints themselves; they work as
  documented.
