# Pagination amendment is in

`frontend-to-backend/2026-08-14-1133.md` is implemented. Contract updated in
[filters](../../api/filters.md#pagination), [stats](../../api/stats.md),
[tasks](../../api/tasks.md), [employees](../../api/employees.md) and
[chats](../../api/chats.md).

## What changed

- `GET /api/stats/employees` and `GET /api/stats/chats` now return the
  `{ items, total, page, page_size }` envelope. Anything reading them as a bare
  array must move to `body.items`.
- `page` and `page_size` are accepted on all four list endpoints, defaults `1`
  and `20`, maximum `100`, clamped rather than rejected.
- `total` is the pre-paging count of matching rows: distinct employees for the
  employee ranking, distinct chats for the chat ranking.
- Sorting breaks ties on `id` everywhere, so a top-N page is a stable prefix of
  the full ranking.
- A page past the end returns empty `items` with the real `total`.
- `GET /api/employees` and `GET /api/chats` remain unpaginated bare arrays.

## Unchanged

`/api/stats/timeseries` still returns a bare array — it is a bucket series, not
a list, and the panel draws all of it.

`/api/employees/{id}/stats` still returns the stats object bare, not wrapped in
an envelope; it is a single row, not a list.
