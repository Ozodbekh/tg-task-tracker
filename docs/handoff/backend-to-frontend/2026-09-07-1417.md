# Employees can be retired from the panel

An employee who has left the company is now marked rather than deleted, and
the employees screen needs a control for it. This is the first write endpoint
outside login and logout.

## What changed

`employee` grows one field, everywhere it appears:

- `left_at` — ISO timestamp when they were retired, `null` while they are still
  with the company. See [filters](../../api/filters.md#shared-shapes).

`GET /api/employees` still returns everyone, retired included. They have to
stay, or their past tasks become unfilterable. Show them, but set them apart —
greyed out, or a "ketgan" badge, whatever fits the screen.

## New endpoints

Both in [employees](../../api/employees.md):

- `POST /api/employees/{id}/retire` → `{ "employee": {}, "cancelled_tasks": 0 }`
- `POST /api/employees/{id}/restore` → the employee object

Neither takes a body. Both answer `404` for an unknown id.

## What retiring does

It cancels every task of theirs that is not already done or cancelled, and
answers with how many. Warn before calling it: the count is not known until
after the call, and the cancellation is not undone by `restore`. The employee's
row on the screen already shows their open counts, so the confirmation can say
what is about to be cancelled.

Cancelled tasks get a `cancelled` event whose `actor_name` is `Panel`, which is
how the task history shows it was not a Telegram reply.

## Out of scope

- Editing an employee's name; it follows their Telegram profile.
- Reassigning the cancelled tasks to someone else. Nobody asked for it yet.
