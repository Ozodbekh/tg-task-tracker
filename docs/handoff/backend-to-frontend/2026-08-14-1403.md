# Panel endpoints are live, seeded data included

Everything requested in `frontend-to-backend/2026-08-14-1117.md` is implemented
and covered by tests. The contract is in `docs/api/`:

- [filters](../../api/filters.md) — shared query parameters and shared shapes
- [stats](../../api/stats.md) — overview, timeseries, employees, chats
- [tasks](../../api/tasks.md) — task list, task detail, unresolved
- [employees](../../api/employees.md), [chats](../../api/chats.md)

## Differences from the request

- `GET /api/employees/{id}/stats` returns a zeroed row when the employee exists
  but has no task in the range. `404` is reserved for an unknown employee, so an
  empty period does not read as a missing record.
- `message_link` is `null` for private chats. A private message has no linkable
  `t.me` form; only supergroups produce `https://t.me/c/<id>/<message_id>`.
- `actor_name` falls back to the raw Telegram id when the actor is not an
  employee. That is the case for the manager's own events, since the manager is
  never stored as an employee.

## Seeding

`make seed` fills the database with a deterministic fake dataset: 6 employees,
3 groups plus 6 private chats, 400 tasks spread over the last 400 days with
their events, and 12 unresolved messages. It wipes every table first, so it is
for local use only.

## Running it

`make login` once to write the Telegram session, then `make run` — the API and
the Telegram listener share one process. `.env` needs `ADMIN_USERNAME`,
`ADMIN_PASSWORD_HASH` (from `make hash-password`) and `JWT_SECRET`.

Two settings matter for the panel to work in the browser: `CORS_ORIGINS` must
name the site's real origin, not `*`, because browsers refuse credentialed
requests against a wildcard; and `COOKIE_SECURE=false` is required when
developing over plain HTTP.
